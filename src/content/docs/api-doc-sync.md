Use this when changing runtime API behavior.

## Why this exists

Route/method coverage in OpenAPI comes from the shared **compile-time route
table** in `crates/runtime-server/src/http/route_table.rs`. Both the real Axum
registration and the generator expand this table: new routes, HTTP verbs and
mounted authentication scopes cannot silently disappear because a text
scraper failed to recognize formatting in `http/mod.rs`. For canonical
operator `/v2` endpoints, request/response shapes and the operator error
envelope are now generated from the actual `schemars::JsonSchema` derives on
serde-backed Rust DTOs (`crates/runtime-server/src/openapi_contracts.rs`).
The two extensible scoped MCP capability/invocation **response bodies** retain
broad `JsonObject` placeholders because their actual handlers return dynamic
`serde_json::Value`; inventing fixed DTOs would misrepresent the wire.

The OpenAPI generator also projects actual Axum `Query<T>` handler DTOs via
`crates/runtime-server/src/openapi_queries.rs` to publish query names,
accepted enum/scalar types and bounded pagination defaults without separate
JSON-body request copies. Only real keyset-page response handlers advertise
`X-Next-Cursor`; JSON-body message cursors and SSE use their separate
contracts. The route table's `scoped_mcp` group carries a distinct agent
Bearer scheme, never the operator token; sidecar-supplied MCP invocation
identity is an optional HTTP header (required for mutating modes).

API docs sync therefore still requires both:

- regenerating `openapi/runtime-server-openapi.yaml`
- updating human docs when behavior changes are not fully captured by schema detail

The release package also carries a **separate** source-derived harness and
three-tool semantic contract artifact (`contracts/runtime-contracts.json`),
generated by the runtime CLI `--write-contracts` and verified with
`--verify-contracts`; it does not replace the OpenAPI snapshot. The offline
`make check-release-layout` gate validates contract bundle parity and an
isolated no-network install without claiming live provider acceptance.
`make check-api-docs-smoke` independently starts a disposable localhost
runtime and verifies real operator HTTP examples, pagination, response
headers, idempotency/restart, and scoped authentication. An inert configured
ACP stub is never invoked; no real provider/device credentials or sessions
are involved.

## Command path

From repo root:

```bash
make api-docs-refresh
make api-docs-status
make api-docs-check
make check-api-docs-smoke
```

What each command does:

- `api-docs-refresh`: runs `./scripts/api-doc-sync.sh refresh` and regenerates the OpenAPI artifact
- `api-docs-status`: runs `./scripts/api-doc-sync.sh status` and prints API/doc sync-relevant file status
- `api-docs-check`: runs `./scripts/api-doc-sync.sh check` and fails if API files changed without doc file changes
- `check-api-docs-smoke`: compiles the runtime binary and exercises documented
  `/v2` request/response behavior against an isolated loopback SQLite fixture
  (no provider/device live testing)

## Sync-relevant files

API-signal files:

- `crates/runtime-server/src/http/`
- `crates/runtime-server/src/openapi.rs`
- `openapi/runtime-server-openapi.yaml`

The guard is intentionally path-based and conservative. Test-only changes under
`crates/runtime-server/src/http/tests/` also count as API signals. For those
changes, regenerate OpenAPI and confirm the artifact is unchanged; document the
verification without implying that a public route or schema changed.

Authenticated Codex live smoke tests use a fixed `gpt-6-luna` model at `low`
reasoning effort, independent of the operator's normal model defaults or
environment model overrides. HTTP smoke tests use the shared `codex_test_model`
and `prepare_codex_smoke_config` helpers to stage disposable provider homes;
workspace-agent smokes also set typed `current_preferences`, and native provider
smokes carry the same preference in their creation policy. The tracked
model-catalog and reasoning-policy tests still intentionally exercise the other
supported values. This changes test fixtures only, not public API behavior or
production model selection.

Authenticated runtime HTTP smoke tests that launch Codex with the GG MCP
sidecar must also serve their test router on an isolated loopback listener.
Bind `127.0.0.1:0`, set `config.server.public_base_url` to the assigned port
before bootstrapping, and keep the gateway alive for provider session creation.
Codex can request GG MCP tools during `thread/start`; pointing it at the
non-serving default URL (or an unrelated service on that port) causes
misleading provider startup timeouts. Restart tests must bind a fresh gateway
for the restarted runtime and update the URL before bootstrapping again.

Docs-signal files:

## Suggested PR checklist

1. Regenerate OpenAPI (`make api-docs-refresh`).
2. Inspect API/docs diff (`make api-docs-status`).
3. Update `/docs/api` for route behavior changes.
4. Update `/docs/endpoint-catalog` for endpoint/query/auth changes.
5. Update deeper narrative docs when behavior affects configuration, providers, architecture, MCP, or operations.
6. Update website docs under `src/content/docs/` when user-facing onboarding changes.
7. Run sync check (`make api-docs-check`).
8. Run isolated HTTP examples (`make check-api-docs-smoke`).
9. Run the relevant Rust/site checks for the changed area.

## What OpenAPI captures well

- route path coverage
- HTTP method coverage
- path parameters
- Rust handler-derived `/v2` query parameter names, types and bounded ranges
- conditional `X-Next-Cursor` keyset response headers (not SSE/message JSON cursors)
- server-minted operator `X-Request-ID` across success, 202/409/412/default
  error and SSE responses, without duplicate header maps or claiming it
  for agent-scoped MCP
- distinct operator and agent-scoped MCP bearer schemes from router groups
- basic request content type for known POST endpoints
- SSE vs JSON response content type
- public vs bearer-protected grouping via route placement
- Rust-derived schemas for workspace authority/operations, operator
  messages/deliveries and provider capability/model/skill discovery, managed
  worktree create/inventory/rebind requests, notice policy, onboarding notice,
  process list/detail, user-turn admission, provider context observations,
  compaction lifecycle/review, and revisioned agent preference/permission
  mutation contracts, workspace-agent roster/recreation/create/archive/restore,
  provider-rebind composite results, edit-rerun and native-effect operator
  reviews, legacy migration status/resolution, retirement-effect review,
  redacted operator event history, hook inspection/approval/effect receipts
  and scoped MCP invocation input, including
  required fields, nullable fields, custom backward-compatible input forms
  and enums
- typed operator `/v2` error responses (including conflict and revision error
  envelopes); `/v2/mcp` has its own agent-facing contract

## What human docs must still explain

- provider/tool-specific semantics and semantic validation that cannot
  be expressed by the serde-derived schema alone
- provider-specific auth/model behavior
- ACP v1 limitations
- SSE replay semantics and cursor precedence
- operational examples and runbooks
- process scheduling, queue/capture semantics, completion delivery, and process/worktree ownership rules
- `/v2` workspace canonicalization, idempotency, and durable-operation semantics
- `/v2` agent-first direct/broadcast context, recipient snapshot, delivery recovery, idempotency, and native-image capability semantics
- team delivery policy and recovery semantics
- deployment and config pitfalls
